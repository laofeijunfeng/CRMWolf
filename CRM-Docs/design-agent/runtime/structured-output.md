# 结构化输出

- **用途：**定义 AI 结构化结果的生产级要求。
- **适用范围：**`/assistant` 的语义解析、活动质量评估和业务建议。
- **权威性：**本文件拥有结构化输出规则。
- **相关规范：**[交互编排策略](interaction-policy.md) · [跟进质量评估](follow-up-quality.md)

## 必须结构化的内容

- 用户意图和置信度。
- 客户名称、客户置信度和澄清问题。
- 跟进内容、下一步动作和原文时间表达。
- 活动质量评分、评分理由、分项和补充问题。
- 时间语义槽位，不包含模型自行换算的最终日期。
- 建议动作、原因、风险、缺失字段和关联对象。
- 候选交互动作、阻塞原因、优先级和是否需要用户响应。

## 校验要求

结构化结果必须通过 Pydantic schema 校验。

置信度不足、客户不明确、字段冲突时应澄清；结构化校验不等于授权，不能据此执行写命令。

模型可以提名候选动作；最终用户回复由服务端依据权威等待选择至多一个主交互。

### 销售助手模型传输边界

共享模型传输层在 HTTP content 或完整 SSE content 拼接后，只去除一次完整外层代码围栏：恰好三个反引号、小写 `json` 或无语言标识、独立开闭栏行，支持 LF/CRLF 及响应两端空白。纯 JSON 保持原有解析语义，JSON 字符串内部的反引号和转义内容不变。

围栏外叙述、多代码块、嵌套围栏、错误语言、四反引号、同行 JSON 或不完整围栏不提取、不修复，继续按无效模型输出处理。去壳后仍执行原 Pydantic、正文完整性和时间/行动证据校验；评分、冻结确认、权限、幂等及写入事务不变。格式错误不增加自动重试。

## 传输模式与失败

使用共享模型传输与原生 `json_schema`；兼容 JSON 模式由团队配置选择，同样必须通过 Pydantic 和证据校验。记录输出模式、模型和失败阶段，不把非法响应当成业务缺口。

## 资源选择

候选集合和引用由服务端生成；模型只从当次候选中提名并提供证据，不生成客户、商机、阶段或任务真实 ID。候选编号须在集合内，提交前重新校验归属和权限。

模型异常、输出非法或证据不足时，不自动绑定对象；按当前等待投影选择或澄清。
