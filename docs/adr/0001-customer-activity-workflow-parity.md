# ADR 0001：客户活动统一 Workflow 与双路径最终化

- **日期：**2026-09-02
- **状态：**Accepted
- **范围：**客户活动（跟进记录、会议纪要）的 Agent 与页面表单处理
- **关联规格：**`CRM-Docs/design-agent/roadmap/customer-activity-workflow-parity-spec.md`

## 背景

旧流程把活动整理、评分、后处理和二级业务建议分散在 Agent graph、页面 API、进程内异步任务和 post-commit 逻辑中。结果是 Agent 已评分后仍可能再次评分，页面任务依赖进程生命周期，活动最终事实与后台副作用的边界不清晰，且删除/retry/restart 时难以保证幂等。

本轮产品确认还明确了：活动本身只有新增和删除；页面活动和会议纪要要保留现有保存后后台处理体验；商机操作必须与活动写入保持原子隔离；本期不做线索、回款和合同。

## 决策

### 1. 两条活动路径，共用 canonical evaluator

- Agent：语义解析 → 内容整理 → 质量评分 → 下一步行动门禁 → `create_final_from_agent()` 一次性写入。
- 页面表单：原文立即写入 `PENDING` → `CustomerActivityAIJob` durable 异步整理/评分 → `finalize_pending_from_ai()` 一次性最终化。
- 两条路径使用同一 canonical rubric/evaluator；Agent 已有最终评分时不再二次评分。
- 评分阈值固定为 `score >= 60`。只保存最终评分；补充前的低分和评分过程不进入业务评分历史。

### 2. 事实写入与后台副作用分离

活动事实通过统一写入服务落库；PostCommit、客户智能刷新、任务投影和商机建议是活动成功后的独立后台动作。任何后台动作失败、重试或取消都不能回滚活动事实。

### 3. durable job 与 revision fence

页面 AI 整理/评分使用可恢复 durable AIJob；后处理使用 revision-scoped PostCommitJob。任务通过唯一自然键、lease、重试和活动 revision 栅栏保证重启、重复投递和并发下不重复写入。

删除活动时不级联删除任务证据；相关未完成任务静默 `SKIPPED`，不再恢复或写回。

### 4. 商机建议保持独立原子

商机建议不塞进活动写入事务。高置信度已有商机直接静默去重；新商机先由 Agent UI 提示“是否创建”，确认后在 Agent 页面内嵌表单补充并提交。商机创建和商机阶段推进是两个不同 command；商机状态变化时静默跳过，不覆盖最新状态、不重复执行、不提示用户。

### 5. 一次性硬切换，不保留旧双轨

删除活动修改、手工 `/process`、`/evaluate`、同步模式和旧 `CustomerActivityProcessingService`。旧 `method` 映射一次性迁移为 `activity_kind`，不保留长期兼容映射。历史已完成活动不重新评分；只接管切换时未完成活动。

### 6. 历史待办确认不承载延期

历史待办确认只用于确认“是否已完成”。交互保留“已完成”“先放着”“不管了”，不再显示或追问“是否延期”。延期继续由独立的跟进任务转换操作承接，避免把完成确认和修改待办时间混成一个原子操作。

已持久化的旧确认 Case、Agent UI 消息和投递快照不做破坏性清洗；所有对外读取边界将旧的延期/取消问题文案规范成完成确认文案。该兼容只改变展示，不改变数据库原始记录，也不改变独立延期能力。

## 后果

### 正面

- Agent 与页面评分行为一致，避免前后评分不一致。
- 活动事实、后台任务和商机操作边界清晰，失败可以独立恢复。
- Worker 重启、重复提交、删除和旧 revision 有确定性语义。
- 前端活动展示不变，同时可以在 Agent UI 中承载轻量确认和商机表单。

### 代价与风险

- 需要新增 AIJob/PostCommitJob 状态、迁移和 recovery scheduler。
- 页面保存后短时间内处于 `PENDING`，UI 必须正确表达异步状态。
- 迁移必须有 watermark、计数和可重跑证据，不能依赖旧 runtime 回滚。
- 商机建议需要独立 durable job 和 Agent UI 交互，不能与活动写入一起交付为一个不可拆分事务。

## 验收要求

以验收矩阵为准，至少覆盖：

- Agent 不重复评分且低分/缺下一步不写入；
- 页面表单立即返回、AIJob 可恢复、失败不丢原文；
- PostCommit/AIJob 在删除、旧 revision、重复投递和 Worker 重启下不产生重复副作用；
- 商机建议不影响活动，已有商机高置信度匹配时静默去重；
- 旧入口和旧 service 在生产运行时代码中清零；
- Alembic 结构迁移与一次性历史迁移可实跑、可重跑并输出证据。
