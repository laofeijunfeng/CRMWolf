# ADR 0003：旧 AI Agent 新输入退役，默认进入销售助手

- **状态：**已接受（CRM-37 方案，用户选择 2A 后批准进入开发）
- **日期：**2026-10-26
- **范围：**Web 导航/默认登录、旧 Web 新提交与飞书旧 Agent 输入；不替代 ADR 0001/0002 的领域与原子边界。

## 背景

菜单、默认落点、运行日志、第三方集成卡和飞书 gateway 是独立入口。只隐藏菜单或保存 bot_enabled=False，不能阻止旧标签页和历史开启团队继续新建旧 Agent 回合。

## 决策

1. 默认与无业务回跳登录进入 `/assistant`，销售助手为销售工作首项；安全业务 URL 的 query/hash、无团队与团队错误恢复、OAuth bind 回跳保持。
2. `/agent` 不再挂载旧页，仅重定向助手并丢弃旧会话参数。移除运行日志设置导航；原日志 URL 在普通 CRM 壳显示“找不到页面 / 这页不存在。”，不请求日志、不跳其他设置。
3. 旧 Web `POST /v1/agent/chat/stream` 在原鉴权/团队和类型校验后返回 HTTP 410，不调用 application、不受理新回合，也不转给销售助手或 Query。历史读取和既有凭证边界不扩权。
4. 飞书入口保留解密、配置归属、App ID、Token、事件身份与 URL verification；合法业务事件立即协议 ACK，不写入站记录/频道会话、不调用 Agent、不发回执/回复/追问/确认，不落跟进。历史 bot_enabled=True 也不能重开。
5. 设置删除机器人整卡和编辑状态，但保留已有 OAuth API/schema/DB 字段；登录保存带回已加载的机器人原值，App Secret 留空仍不替换。飞书登录与独立审批通知保持。
6. **已受理回合策略为 2A：**保留既有 detached worker、lease 恢复和原子语义，允许晚到旧写入；不撤销、不重放成功原子。不为旧飞书回合补发消息。新的确认、补充和表情仍属于被关闭的新输入。

## 结果与风险

销售助手和页面表单仍可新增客户活动、确认商机和独立推进阶段；60 分、审批、多租户和 revision 栅栏不变。入口退役不等于清空历史或取消全部旧执行。不清凭据、不删表、不扩成全站404，也不做整体旧代码清理。Q10A 追加一条不破坏历史的桥接迁移 `157_merge_assistant_conversation_paths`：把已恢复的 154–156 旧链和当前 `02352b41bcb6` 收成单一 head。它不删除旧消息或会话、不 stamp、不直接修改原库；同一团队用户出现重复会话时拒绝合并。

## 验证与回滚

通过公开 webhook/service 与旧 Web HTTP 的回归断言无派发/发送/写入，并保留 application 恢复、助手、表单与审批保护测试。导航、深链接、设置保存与缺页用 Vitest 和真实 Playwright 页面验证。

回滚仅还原本次代码；不删除业务事实、不重放已成功命令。回滚会重新开放旧入口，必须作为显式发布决定，不应通过改历史机器人开关冒充回滚。
