# ADR 0004：销售助手输入噪音无损标注（第一批）

- **状态：**已接受（CRM-95 方案，用户回复「进入开发」后批准）
- **日期：**2026-11-10
- **范围：**销售助手分类调用的噪音标注、服务端核对、时间与渠道门禁的降噪，以及确认卡摘要；不改页面表单路径、不改原文存储。

## 背景

用户粘贴会议转写或聊天记录时，`13:45 张总：` 这类发言时间戳会被当成业务时间去问角色或日期。纪要里只是提到「邮件」「电话」，也会让会议类型和跟进渠道打架，于是追问活动类型。原来的正则豁免只覆盖少数格式，换个写法就失效。

## 决策

1. 噪音由分类调用标注：`KindDecision.noise_spans` 里每条 `ModelNoiseSpan` 只有 `kind`、`raw_text`、`quote_start`、`quote_end`，`extra=forbid`。第一批只有 `SPEAKER_TIMESTAMP` 和 `CHANNEL_MENTION` 两类。标注不合法时整次分类失败，走现有的模型失败路径。
2. 服务端只核对、不识别（`noise.py`）：
   - 用 `locate_quote` 在本段原文里定位，定位不到就丢弃。
   - `SPEAKER_TIMESTAMP` 和 `find_time_spans` 扫到的业务时间片段重叠，或者两者之间只隔空白，就丢弃。
   - `CHANNEL_MENTION` 和分类自己的 `evidence_quote` 重叠时丢弃。
3. 标注只能减少提问：
   - 时间证据跳过完全落在发言时间戳里的引用和动作。
   - 渠道判断和活动类型追问使用把渠道提及替换成空格的文本。
   - 原文、引用和偏移一律不改。
   - 原有的正则豁免保留，作为兜底。
4. 粘贴记录的某一行以 `张总：` 这类非我方发言人开头时，行内的「我/我们」属于该发言人，不再强制判为销售的下一步，改由模型的角色决定。
5. 核对后的标注存入 `TaskDraft.input_noise`。确认卡和冻结命令带上 `ignored_noise_summary`（例如「已忽略 3 处发言时间」），并纳入指纹。卡片用灰色说明文字展示，不另加交互。

## 结果与风险

- 转写和聊天粘贴少问无意义的时间与类型问题。业务时间被标成噪音时会被核对规则丢弃，问题照常出现。
- 模型漏标时行为和以前一样，不会更差。
- `POLICY_VERSION` 不变，已持久化的证据包仍能通过校验。
- 风险：「备注：我们下周联系」这类冒号前缀也会被当成发言人，此时角色交给模型决定，可能多问一次，但不会漏掉下一步。
- 渠道边界：销售自己写的后续联系方式（如「明天电话跟进」「再电话确认」）算本次渠道；会议纪要/转写中被提到的电话、微信、邮件，以及过往沟通习惯，只标为 `CHANNEL_MENTION`。

## 验证与回滚

- `tests/unit/test_assistant_input_noise.py` 覆盖验收 1–9 和核对规则，其中包括端到端的确认卡和冻结命令。
- 投影测试和 Vitest 覆盖卡片摘要只出现一次。
- 真实模型上用脱敏样本做了前后对比，`/assistant` 有前后截图。

回滚只需还原代码。注意：回滚到旧版本前需取消或完成进行中的助手任务，否则旧版 `TaskDraft(extra="forbid")` 加载含 `input_noise` 的草稿会 500；已完成且旧数据未含该字段的任务不受影响。
