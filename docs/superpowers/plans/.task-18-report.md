## Fix

Final branch-review authorization and filter defects:

- Contract board no longer clears own scope when `customer_id` is present. A `contract:view:own` caller still sees only their own contracts in summary, trends, counts, and previews, matching `get_contracts`.
- Excluding a known payment approval status now uses `expression IS NULL OR expression != value`. The previous `NOT (expression IS NOT NULL AND expression = value)` was parsed by MySQL as `(NOT expression IS NOT NULL) AND expression = value`, which removed approved, pending, and rejected rows. Excluding `unclassified` still uses `expression IS NOT NULL`.
- Payment-record detail applies the same `Contract.creator_id` own scope used by the list and board. An own-scope caller receives 404 for another creator's numeric ID. The detail builder no longer repeats the payment-plan owner check after that decision. Idempotent resolve is unchanged.
