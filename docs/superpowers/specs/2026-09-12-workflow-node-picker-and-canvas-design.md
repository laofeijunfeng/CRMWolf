# 工作流画布节点选择器与 CRM 业务节点设计

- 日期：2026-09-12
- 状态：已确认，待用户审阅规格
- 上游：`docs/superpowers/specs/2026-09-10-workflow-canvas-design.md`
- 关联页面：`/settings/approval-flows-new`

## 1. 背景与用户决策

当前工作流编辑器将全部节点平铺在左侧 Palette 中。节点数量扩展后会出现三个问题：

1. 节点类型越来越多，左侧列表难以扫描和维护；
2. 用户无法直观看出“新节点应该插入流程的哪个位置”；
3. 画布与节点配置的层次不清晰，和参考的自动化编辑器体验有差距。

本设计已确认以下方向：

- 画布采用参考图的流程化视觉：画布为主工作区，节点按流程关系展示；
- 不再把所有节点长期平铺在左侧；
- 节点之间显示“＋”插入入口；
- 点击“＋”打开分类节点选择弹窗；
- 选择节点后，插入到被点击的连接位置，并自动维护连接；
- 右侧面板只负责配置当前选中节点；
- 业务资源节点拆成独立节点，不使用一个泛化的“创建资源”节点。

## 2. 目标与非目标

### 2.1 目标

- 将节点添加入口从“左侧平铺列表”升级为“流程位置 + 节点库”；
- 支持在已有边中间插入节点：`A → B` 变为 `A → 新节点 → B`；
- 支持在末端节点后追加节点：`A` 变为 `A → 新节点`；
- 支持从工具栏打开同一节点库，创建根节点或孤立节点；
- 通过分类、搜索和节点摘要承载持续增长的节点目录；
- 为 CRM 业务节点建立稳定的注册表、DSL 类型和配置面板边界；
- 保持当前草稿保存、校验、乐观锁和权限行为不变。

### 2.2 非目标

本次不实现：

- Activepieces Adapter 或 Activepieces Flow 同步；
- Activepieces 执行、重试、运行历史和连接器市场；
- CRM 业务动作 API 的完整执行闭环；
- 通用表达式编辑器、循环、子流程、自动布局引擎；
- 旧 `/settings/approval-flows` 路由替换；
- 一次性迁移全部潜在业务节点。

新增 CRM 资源节点在本阶段完成注册表、配置 UI、DSL 持久化和结构校验；实际运行时写入仍由后续受控 API / Adapter 任务承接。

## 3. 信息架构

### 3.1 编辑器整体布局

```text
┌──────────────────────────────────────────────────────────┐
│ 返回 / 工作流名称 / 草稿状态 / 校验 / 保存 / 发布        │
├───────────────────────────────────────┬──────────────────┤
│                                       │                  │
│             Vue Flow 画布             │ 当前节点配置面板 │
│                                       │                  │
│       节点                              │                  │
│        ↓                              │                  │
│       ＋                              │                  │
│        ↓                              │                  │
│       节点                              │                  │
│                                       │                  │
├───────────────────────────────────────┴──────────────────┤
│ 缩放 / 适配 / 画布辅助控制                                │
└──────────────────────────────────────────────────────────┘
```

- 画布占据主要空间；
- 右侧配置面板固定在编辑器右侧，独立垂直滚动；
- 不再渲染固定宽度的左侧 `WorkflowNodePalette`；
- 顶部保留工作流名称、校验状态、保存和发布操作；
- 画布底部保留缩放、适配视图和选择/平移控制。

### 3.2 顶部状态区

参考图中的“有未发布的更改”反馈，编辑器顶部增加明确状态：

- `草稿`：工作流尚未发布；
- `有未保存的更改`：节点、边或配置发生变化；
- `校验通过` / `有 N 个问题`：复用现有前端校验结果；
- `保存草稿`：保存当前 DSL；
- `发布`：沿用既有状态 API 和权限规则，不在本次改造中改变发布语义。

### 3.3 节点卡片

节点卡片统一显示：

- 类型图标；
- 节点名称；
- 节点类别徽标：触发器、CRM 业务、动作、控制、审批；
- 配置摘要；
- 配置状态：已配置、待配置或错误；
- 选中态边框；
- 错误态红色边框与错误摘要。

节点编号只作为画布视觉辅助，不写入 DSL，不作为节点 ID。编号按当前画布拓扑顺序展示；分支场景使用局部步骤编号或不显示编号，避免把视觉编号误解为执行顺序。

## 4. “＋”插入交互

### 4.1 插入槽类型

每个可插入位置对应一个明确的 insertion context：

```ts
interface WorkflowInsertContext {
  kind: 'between-edge' | 'after-node' | 'root'
  sourceNodeId?: string
  targetNodeId?: string
  edgeId?: string
}
```

#### A. 两个节点之间

已有边：

```text
A ─────────→ B
      ＋
```

点击“＋”后选择节点，图变为：

```text
A ─→ 新节点 ─→ B
```

实现要求：

- 删除原 `A → B` 边；
- 创建 `A → 新节点` 和 `新节点 → B` 两条新边；
- 新边使用新的边 ID；
- 保留 A、B 节点配置和位置；
- 新节点自动选中并打开右侧配置面板。

#### B. 末端节点之后

```text
A
↓
＋
```

选择节点后创建：

```text
A → 新节点
```

如果末端存在多个 outgoing 分支，每条分支边各自显示独立“＋”；用户点击哪条边，就只在那条边上插入，不根据数组顺序猜测来源。

#### C. 根节点 / 孤立节点

以下情况使用顶部 `添加节点` 按钮打开节点库：

- 画布为空；
- 用户明确希望创建新的入口节点；
- 图中存在多个分支末端且用户不想绑定到某条边。

根入口选择节点后，在画布可视区域中心附近创建，不自动连接。若当前没有 Trigger，用户可以创建 Trigger；若已有 Trigger，节点库中 Trigger 类型置灰。

### 4.2 节点库弹窗

点击“＋”或顶部“添加节点”后打开同一个 Dialog，不使用两套节点选择逻辑。

弹窗结构：

```text
┌─────────────────────────────────────────────┐
│ 选择节点                              关闭  │
├─────────────┬───────────────────────────────┤
│ 推荐        │ 搜索节点                       │
│ 触发器      ├───────────────────────────────┤
│ CRM 业务    │ 节点卡片                       │
│ 动作        │ 节点卡片                       │
│ 控制        │ 节点卡片                       │
│ 审批        │ 节点卡片                       │
└─────────────┴───────────────────────────────┘
```

交互规则：

- 打开后焦点进入搜索框或第一个可选节点；
- 支持键盘 `Esc` 关闭，关闭后焦点返回触发“＋”按钮；
- 分类切换不改变 insertion context；
- 搜索匹配节点名称、描述和类型 key；
- 点击节点卡片立即完成选择，不增加二次确认；
- 选择完成后弹窗关闭，节点插入并自动选中；
- 不可用节点显示原因，例如“当前工作流已有一个触发器”；
- 移动端使用接近全屏的 Dialog，节点卡片单列排列。

### 4.3 自动插入位置

- between-edge：新节点位置取源节点和目标节点位置的中点，并沿主方向留出间距；
- after-node：新节点位于源节点下方或主流程方向的下一个网格位置；
- root：使用画布视口中心转换后的 Flow 坐标；
- 本次不引入完整自动布局；仅提供确定性的局部位置计算；
- 用户仍可自由拖动节点。

## 5. 节点目录与首批新增节点

### 5.1 分类

```text
trigger     触发器
crm         CRM 业务
action      动作
control     控制
approval    审批
```

当前已有节点继续保留：

- `trigger.opportunity_stage_changed`：商机阶段变化；
- `approval.step`：审批节点；
- `control.condition`：条件分支；
- `action.create_follow_up_task`：创建跟进任务；
- `action.notify`：发送通知。

### 5.2 首批独立 CRM 业务节点

用户选择拆成独立节点，首批增加：

#### `crm.create_customer` — 创建客户

必填配置：

- `account_name`：客户公司名称；
- `city`：所在城市。

可选配置：

- `industry`；
- `address`；
- `company_scale`；
- `owner_strategy`；
- `default_procurement_method_id`。

#### `crm.create_contact` — 创建联系人

必填配置：

- `customer_ref`：关联客户来源；
- `name`；
- `gender`；
- `position`；
- `mobile`。

可选配置：

- `is_decision_maker`；
- `email`；
- `wechat_id`；
- `remark`。

#### `crm.create_opportunity` — 创建商机

必填配置：

- `customer_ref`；
- `total_amount`；
- `user_count`；
- `license_type`；
- `purchase_type`；
- `expected_closing_date`。

可选配置：

- `opportunity_name`；
- `subscription_years`；
- `decision_maker_count`；
- `procurement_method_id`；
- `procurement_stage_id`；
- `owner_strategy`。

`customer_ref` 先作为 DSL 配置字段保存，允许后续绑定触发事件、上游节点输出或固定客户。动态字段表达式和运行时解析不在本次 UI 改造范围内，但字段命名必须为后续绑定保留空间。

### 5.3 注册表契约

前端和后端各自维护已知节点注册表，类型 key 必须一致：

```text
crm.create_customer
crm.create_contact
crm.create_opportunity
```

前端注册表新增：

- label；
- category；
- icon；
- defaults；
- requiredFields；
- summary；
- config panel。

后端 DSL 校验新增：

- known node type；
- required config fields；
- 类型和配置结构校验。

执行权限、幂等、审计和 Activepieces Piece 在后续 CRM 受控动作任务中实现。

## 6. 右侧配置面板

右侧面板沿用现有动态组件机制，但视觉和交互调整为参考图风格：

- 面板头部显示图标、节点名称、节点类别和关闭/取消选择按钮；
- 配置字段按业务分组；
- 必填字段显示红色星号；
- 异步选项数据加载显示局部 loading；
- 422 字段错误显示在对应字段或面板顶部；
- 配置更新实时写入节点 data；
- 保存工作流仍保存整张 DSL，不单独调用资源创建 API；
- 节点删除放在面板底部的危险操作区，并保留现有边清理行为。

## 7. DSL 与保存边界

DSL 结构不变：

```json
{
  "schema_version": 1,
  "nodes": [
    {
      "id": "node-1",
      "type": "crm.create_customer",
      "position": { "x": 100, "y": 240 },
      "config": {
        "account_name": "示例客户",
        "city": "上海"
      }
    }
  ],
  "edges": []
}
```

新增节点只扩展 `type` 和 `config`，不修改顶层结构。保存仍由现有 workflow API 完成，并继续使用：

- 团队隔离；
- 前端保存前校验；
- 后端 DSL 校验；
- 乐观锁；
- 409 刷新重试；
- 422 节点错误回显。

## 8. 权限、错误与可访问性

- 节点库入口服从工作流创建/编辑权限；
- 节点选择弹窗不改变权限边界；
- 不具备配置所需数据权限时，节点仍可展示但配置项明确提示不可用，或按现有权限策略隐藏；
- Trigger 唯一约束在节点库和校验层双重保证；
- 所有浮层具备标题、关闭按钮、Esc 关闭和焦点回收；
- 节点卡片、加号按钮和边插入槽具备可读 aria-label；
- 窄屏下右侧配置面板转换为抽屉，不能导致画布横向滚动。

## 9. 测试与验收

### 前端单元测试

- 节点目录按分类渲染；
- 搜索过滤节点；
- Trigger 已存在时正确禁用；
- 点击 between-edge 插入节点并拆分原边；
- 点击 terminal plus 追加节点并创建边；
- 多分支场景按具体边插入，不猜测其他边；
- 根入口创建孤立节点；
- 新增 CRM 节点 defaults、必填字段和 summary 正确；
- 保存 payload 保持 DSL 顶层结构，并包含新节点类型。

### 后端单元测试

- 三个新节点类型被注册；
- 合法配置通过；
- 缺少 required config 返回 422；
- 未知节点类型仍被拒绝；
- 目标为 Trigger、自环、悬空边规则不变。

### 浏览器冒烟

1. 打开 `/settings/approval-flows-new`；
2. 创建空白工作流；
3. 添加商机阶段变化 Trigger；
4. 点击节点下方“＋”；
5. 在分类弹窗搜索并选择“创建客户”；
6. 验证节点插入、边自动连接和右侧配置面板打开；
7. 再点击下一条“＋”，选择“创建联系人”；
8. 验证连续流程和节点配置摘要；
9. 保存并重新打开，确认 DSL 节点和边完整往返。

## 10. 分阶段交付

### Slice A：画布和节点选择交互

- 移除左侧平铺 Palette；
- 增加画布插入槽和顶部根节点入口；
- 实现分类搜索 Dialog；
- 实现 after-node / between-edge / root 三种插入上下文；
- 保持现有五个节点可用。

### Slice B：独立 CRM 节点

- 增加创建客户、创建联系人、创建商机注册表；
- 增加配置面板和前端校验；
- 同步后端 DSL 白名单和结构校验；
- 完成 DSL 保存往返测试。

### Slice C：视觉与体验收尾

- 顶部草稿/发布状态条；
- 节点卡片状态、步骤信息和画布控制；
- 右侧面板视觉调整；
- 响应式、键盘和焦点验收。

运行时业务写入与 Activepieces 适配仍作为后续独立任务，不与本次画布交互改造混合交付。
