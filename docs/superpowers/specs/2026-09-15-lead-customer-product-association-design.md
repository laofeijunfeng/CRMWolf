# 线索与客户意向产品关联设计

- 日期：2026-09-15
- 状态：已确认，待实施
- 范围：线索、客户、线索转客户、商机默认值；产品目录空态提示
- 上游决定：方案 A。线索/客户只记意向产品，不记模块；商机才记产品 + 模块。本期 UI 每条线索/客户只选 1 个产品，存储用关联表预留以后多产品。一个客户以后对两套产品有意向时，拆成两个商机，不把一个商机改成多产品。
- 相关实现：`CRM-Server/app/models/lead.py`、`CRM-Server/app/models/customer.py`、`CRM-Server/app/models/opportunity.py`、`CRM-Server/app/crud/customer.py`、`CRM-Client/src/components/LeadFormDialog.vue`、`CRM-Client/src/components/dialogs/CustomerFormDialog.vue`、`CRM-Client/src/components/LeadConvertDialog.vue`、`CRM-Client/src/components/dialogs/OpportunityFormDialog.vue`

## 1. 背景与目标

产品目录已经存在。商机创建/编辑强制绑定一个启用产品和至少一个模块。线索和客户没有产品字段。结果是：

- 商机默认团队第一个启用产品，不看客户意向
- 线索转客户不携带产品
- 新团队没有产品时，商机表单只显示「暂无可用产品」和提交后的「请选择产品」，没有说明下一步

销售在线索阶段已经知道客户对哪个产品感兴趣，到商机才知道要买哪些模块。客户以后可能同时跟进两套产品，但每一笔成交仍是一单一品。

目标：

1. 创建/编辑线索、创建/编辑客户时必选一个启用产品，不选模块
2. 线索转客户自动带上线索产品，转化时可改
3. 创建商机时，客户已有产品则默认该产品及其 `BASE` 模块；没有则沿用「第一个启用产品」
4. 商机仍可改产品和模块；换产品清空旧模块并带上新产品 `BASE`
5. 线索/客户存储用关联表，即使本期 UI 只允许 1 条
6. 空产品目录给出可执行提示，而不是只报字段为空

## 2. 非目标

- 不改合同、License、回款、发票
- 不把商机改成多产品；`Opportunity.product_id` 保持标量
- 不给线索/客户暴露模块选择
- 不回填历史线索/客户的产品
- 不在空目录时自动创建产品
- 不改产品目录 CRUD 和基础模块规则
- 不把客户产品做成不可改的死绑定，也不回写已有商机或旧线索

## 3. 方案选择

采用「线索/客户关联表 + 商机继续一单一品」。

放弃：

- 线索/客户写 `product_id` 标量，以后再迁关联表：实现最快，但客户要 2 个产品时必须再迁一次读写切面
- 一个商机挂两个产品：现有 `product_id` 和「模块必须属于所选产品」会搅在一起，金额、授权、合同都要拆
- 线索/客户也存 `BASE` 模块：线索阶段不需要模块，会把「意向」和「成交配置」混在一起

「客户买两套」用两个商机表达。关联表现在就建，UI 先限 1 条。

## 4. 领域分层

| 对象 | 记什么 | 不记什么 |
|---|---|---|
| 线索 | 感兴趣的产品 | 模块 |
| 客户 | 意向产品（从线索继承，可改） | 模块 |
| 商机 | 成交配置：一个产品 + 该产品下的模块 | 客户未选的其他产品 |

选产品时，UI 不出现模块。创建商机时，系统把该产品的 `BASE` 模块写入商机模块关联。

## 5. 数据模型

新增两张团队隔离的关联表。不用线索/客户上的标量 `product_id`。

```text
crm_lead_products
  lead_id              FK crm_leads.id ON DELETE CASCADE
  product_id           FK crm_products.id ON DELETE RESTRICT
  team_id              团队 ID，与线索/产品同团队
  PRIMARY KEY (lead_id, product_id)
  INDEX (team_id)
  INDEX (product_id)

crm_customer_products
  customer_id          FK crm_customers.id ON DELETE CASCADE
  product_id           FK crm_products.id ON DELETE RESTRICT
  team_id              团队 ID，与客户/产品同团队
  PRIMARY KEY (customer_id, product_id)
  INDEX (team_id)
  INDEX (product_id)
```

约束：

- `lead.team_id == product.team_id == row.team_id`
- `customer.team_id == product.team_id == row.team_id`
- 本期应用层强制每条线索/客户最多 1 条关联。表结构不设「每客户一行」的唯一约束，以便以后放开多产品
- 停用产品：历史关联保留，读取仍返回原产品名；新写入和默认值只允许启用产品
- 删除产品：若仍被线索、客户或商机引用，返回明确 409，沿用产品目录「被业务引用不可删」规则

商机表不改结构：

- `crm_opportunities.product_id`：一单一品
- `crm_opportunity_product_modules`：所选产品下的模块

Alembic 新增 migration，挂在 `133_opportunity_product_assignment` 之后。

## 6. 写入与继承

### 6.1 线索

创建、编辑必填一个启用产品。内部写入 `crm_lead_products` 的唯一一行。编辑换产品时替换该行，不累积。

校验与商机 `assign_product` 的产品部分相同：团队内、启用中。不校验模块。

### 6.2 直接创建客户

创建、编辑同样必填一个启用产品，写入 `crm_customer_products` 的唯一一行。编辑换产品只改客户意向，不修改该客户已有商机。

### 6.3 线索转客户

`convert_from_lead` 在同一事务里拷贝线索产品到客户。

转化请求增加可选 `product_public_id`：

- 传入：用传入值，须为启用产品
- 不传：用线索当前产品
- 线索没有产品（历史数据）且请求也没传：400，文案「请选择产品」

转化弹窗默认选中线索产品，允许改。行为对齐现有默认采购方式：转化时可补/可改，不回写线索。

### 6.4 商机默认值

创建商机（页面表单、Agent、客户详情里新建）按下面顺序填默认值，用户可改：

1. 客户有启用产品：该产品 + 其 `BASE` 模块
2. 客户没有产品，或客户产品已停用：按 `crm_products.id` 升序取团队第一个启用产品 + 其 `BASE` 模块
3. 团队没有启用产品：不默认，提交被拦住，提示见第 8 节

编辑已有商机：保留已保存的产品和模块，不因客户后来改意向而覆盖。

换产品：清空旧模块，带上新产品 `BASE`。这是现有商机表单行为，保持不变。

以后客户有多条产品时，第 1 步取关联表中 `product_id` 最小的一条，直到 UI 做成显式选择。本期每客户最多一条，该规则无可见差异。

## 7. API 契约

对外写入统一用单个 `product_public_id`。内部写关联表。

读取同时给标量和数组，数组为以后多选预留：

```json
{
  "product_public_id": "prd_...",
  "product_name": "CRM",
  "products": [
    { "public_id": "prd_...", "name": "CRM" }
  ]
}
```

规则：

- 本期 `products` 最多 1 条；`product_public_id` / `product_name` 与该条一致
- 历史记录没有关联时，三个字段分别为 `null` / `null` / `[]`
- 以后放开多选时，写入增加 `product_public_ids`，读取继续用 `products`

必填：

| 操作 | 产品 |
|---|---|
| 新建/编辑线索 | 必填启用产品；编辑历史无线索产品的记录时，保存前必须补选 |
| 新建/编辑客户 | 必填启用产品；编辑历史无产品客户时，保存前必须补选 |
| 线索转客户 | 必填；可从线索继承 |
| 新建商机 | 必填产品 + 至少一个模块 |
| 读取历史线索/客户/商机 | 允许空 |

错误：

- 未选产品：400「请选择产品」
- 产品不存在或不属于当前团队：404「产品不存在」，不泄露其他团队对象
- 产品已停用且用于新写入/默认值：400「请选择启用中的产品」
- 团队没有启用产品：400「团队还没有可用产品，请联系管理员在「设置 → 产品管理」创建」
- 无 `product:view` 却拉产品列表：403，前端文案「没有产品查看权限」

Agent / 画布 / 导入：

- `AgentLeadCreatePayload`、`AgentCustomerCreatePayload` 增加必填 `product_public_id`
- 缺产品走补全表单，字段是产品选择，不让模型填模块
- Agent 创建商机：客户已有产品则默认该产品，不要总选目录第一项
- 画布 `crm.create_lead` / `crm.create_customer` 配置增加产品对外 ID
- 批量导入缺产品：该条失败，错误「缺少产品」，不整批静默跳过

列表查询 catalog：

- 线索、客户增加 `product_name`，用关联表 join `crm_products.name`
- 搜索覆盖产品名
- 重新生成 `listQueryCatalogManifest.json`

停用产品仍出现在该线索/客户/商机的只读展示中；选择器和新建默认值只列出启用产品。若编辑中的当前值已停用，选择器保留该项以便用户看见现状，但不能再次提交停用产品，除非改成启用产品。

## 8. 前端

### 8.1 线索表单 / 客户表单

- 产品控件与获客来源同级，必选
- 复用商机的产品分段选择；不渲染模块多选
- 空目录文案：「团队还没有可用产品，请联系管理员在「设置 → 产品管理」创建」
- 当前用户有 `product:create` 时，可显示「去创建产品」并跳到 `/settings/products?action=create`
- 销售默认没有 `product:create`，只显示联系管理员，不显示创建入口
- 产品列表 403：toast「没有产品查看权限」，不要通用「操作失败」

### 8.2 线索转客户

- 增加产品选择，默认线索产品
- 线索没有产品时，转化当场必选
- 提交带 `product_public_id`

### 8.3 商机表单

只改默认值来源，不改模块交互：

1. 客户启用产品优先
2. 否则第一个启用产品
3. 模块默认该产品 `BASE`
4. 换产品仍清空并带上新产品 `BASE`
5. 「请选择产品」只在提交后显示

### 8.4 列表与详情

- 线索列表、客户列表增加「产品」列，只显示产品名；空为 `-`
- 商机列表保持产品名主行 + 模块辅行
- 线索/客户搜索 placeholder 加上产品
- 客户详情、线索详情展示产品名
- 本期不把客户产品列做成「CRM、OA」

## 9. 空目录与权限

产品仍是必填。新团队没建产品时，线索、客户、商机都建不了。这是有意挡住，但必须说清楚原因和下一步。

| 场景 | 文案 |
|---|---|
| 表单打开，团队无启用产品 | 「团队还没有可用产品，请联系管理员在「设置 → 产品管理」创建」 |
| 提交仍无产品 | 前端拦住；后端 400 同上 |
| 有 `product:create` | 额外提供「去创建产品」 |
| 无 `product:view` 拉目录 | 「没有产品查看权限」 |
| 设置 → 产品管理且无 `product:create` | 现有「暂无产品」不够；空态补一句「你没有创建产品的权限，请联系团队管理员」 |
| Agent 补全 | 提示选产品；若目录为空，说明团队还没有产品，不要让用户填对外 ID |

不在商机/线索表单里内嵌完整产品创建表单。创建产品仍走设置中心，权限边界保持 `product:create`。

## 10. 以后多产品

本期应用层限制：

- 写入 `product_public_id` 单个
- 每条线索/客户关联表最多 1 行
- 商机仍一单一品

以后放开客户多产品时：

- 关联表不用迁
- 写入改为 `product_public_ids`
- 响应已有 `products[]`
- 商机默认值从「唯一一条」改为「用户挑选客户已有产品之一」
- 一个客户跟进 CRM 和 OA = 两个商机，不是一个商机两行产品

本设计不实现多选 UI。

## 12. 风险

- 空目录会把卡点从商机前移到线索。必须把提示做清楚，否则销售会以为表单坏了
- 历史线索/客户没有产品。转化和直接建商机必须能补选，不能假设关联一定存在
- 客户改意向不改已有商机。列表上客户产品和商机产品可能不一致，这是正确的：客户意向 vs 成交配置
- 关联表预留多行，但 API 仍收单个 ID。测试必须钉住「写入第二行会被替换而不是追加」，避免半开多产品状态
