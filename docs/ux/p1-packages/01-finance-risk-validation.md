# P1-PKG-01 财务与高风险操作风险验证 PRD

- **定位**：P1 改造前置风险验证包
- **优先级**：P1，若发现不可恢复数据损失或重复写入则升级为 P0
- **适用流程**：回款登记、审批提交、删除、退回、输单、转移、撤回、驳回、冲红
- **不含范围**：Agent / AI 自动化

## 1. 目标

确认高风险写操作是否存在重复写入、状态不一致、请求超时后无法判断最终结果或不可恢复问题，并形成前后端共同遵守的状态和恢复契约。

## 2. 当前问题

回款涉及金额、日期、合同和回款计划等业务事实；审批和状态推进可能出现“请求已提交但前端未收到响应”的情况。仅显示成功 Toast 不能证明最终状态已落库，失败后直接重试也可能造成重复写入。

## 3. 本期需求

1. 为回款登记、审批提交和高风险状态变更建立操作清单；
2. 确认每个写操作是否具备幂等键或等价的重复请求保护；
3. 定义请求超时后的最终状态查询方式；
4. 明确每个操作是可撤销、可重试、可补偿还是只能人工恢复；
5. 明确部分成功、并发修改和状态冲突的业务语义；
6. 记录操作前状态、操作后状态、审计字段和责任边界；
7. 输出“写操作状态矩阵”和 P0 风险结论。

## 4. 独立验收标准

- 回款登记至少完成重复点击、网络超时、刷新、返回和并发修改测试；
- 审批提交至少完成重复点击、超时、驳回和撤回测试；
- 超时后可以查询最终状态，不依赖用户猜测；
- 明确哪些操作可自动重试，哪些操作必须先查询最终状态；
- 所有不可撤销操作都有人工恢复入口和责任人；
- 发现重复写入、无法查询最终状态或不可恢复数据损失时，相关流程不得进入普通 P1 上线。

## 5. 交付物

- 高风险操作清单；
- 写操作状态矩阵；
- 幂等与最终状态验证记录；
- 撤销、补偿和人工恢复策略表；
- P0 风险结论及后续阻断项。

## 6. 依赖与后续拆票

依赖审批、回款及状态推进接口提供最终状态和审计信息。建议拆为：接口状态核查、重复提交测试、超时恢复测试、业务恢复策略确认、风险结论评审。
