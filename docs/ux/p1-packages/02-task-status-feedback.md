# P1-PKG-02 统一任务状态与结果反馈 PRD

- **定位**：跨页面共享状态反馈改造包
- **优先级**：P1
- **适用模块**：DataTable、CustomerDetailSheet、CustomerEdit、商机、合同、审批、回款
- **不含范围**：Agent / AI 自动化状态模型

## 1. 目标

让用户始终知道系统正在处理什么、当前结果是什么以及下一步可以做什么，减少重复点击、刷新和误判。

## 2. 当前问题

当前列表、详情和表单分别管理 loading、empty、error、toast 和 processing；部分失败只通过 Toast 告知，部分详情加载失败会返回上一页，选项加载失败可能只写日志。普通业务请求和长任务的结果表达不完全一致。

## 3. 本期需求

统一定义并在共享组件中实现：加载中、空数据、筛选无结果、权限不足、保存中、成功、失败、可重试、部分成功、处理中和已取消。

每种状态必须明确：

- 状态文案和发生了什么；
- 展示位置和是否阻塞页面；
- 用户可执行动作；
- 是否需要持久化；
- 键盘和辅助技术如何感知。

产品行为要求：

1. 保存中禁止重复提交；
2. 失败不清空输入、不自动跳转；
3. 成功反馈包含对象名称和最终状态；
4. 长任务离开当前页面后仍可找回状态；
5. 高风险操作不只依赖短时 Toast；
6. 空状态区分无数据、筛选无结果、尚未创建和无权查看。

## 4. 独立验收标准

- 列表、详情、表单、审批和回款均有统一状态表现；
- 在断网、超时、500、权限不足和部分成功场景下无需刷新即可恢复；
- 保存中不会产生重复请求；
- 失败后可直接重试或进入人工处理；
- 审批和回款成功后能看到最终业务状态；
- 状态不只依赖颜色，并能被辅助技术感知。

## 5. 交付物

- 任务状态协议；
- 状态文案与反馈位置表；
- 共享状态组件或 composable；
- 列表、详情、表单迁移示例；
- 异常状态回归测试清单。

## 6. 后续拆票

建议拆为：状态枚举与文案、列表状态迁移、详情状态迁移、表单保存状态、长任务持久状态、错误重试组件、状态无障碍测试。
