# P1-PKG-04 对象上下文与详情层级收敛 PRD

- **定位**：详情信息架构与对象导航改造包
- **优先级**：P1
- **适用模块**：CustomerDetailSheet、商机、合同、回款计划、回款记录
- **不含范围**：Agent / AI 自动化

## 1. 目标

让用户在客户、商机、合同和回款对象之间切换时，始终知道当前对象、上一级对象、返回位置和关闭范围。

## 2. 当前问题

`CustomerDetailSheet` 同时承载客户档案、客户信息、客户活动和项目旅程，并可能继续打开商机、合同及多个业务 Dialog。Sheet、Dialog、页面和内部滚动叠加后，用户容易混淆返回、关闭和取消。

## 3. 产品模型

统一对象上下文栈：

```text
客户 → 商机 → 合同 → 回款计划 / 回款记录
```

## 4. 本期需求

- 持续显示当前对象名称、对象类型和关键状态；
- 提供明确的返回上一级和关闭整个流程入口；
- 区分返回、关闭和取消的文案与行为；
- 关联对象优先复用当前上下文，不无限叠加模态层；
- 客户档案、活动、客户信息和项目旅程建立清晰任务边界；
- 页面级、列表级、行动作、详情 Footer 和关联对象动作按统一位置呈现；
- 控制页面、表格、Sheet、Dialog 的滚动容器数量；
- 打开、返回、关闭和提交后焦点恢复到可预测位置。

## 5. 独立验收标准

- 用户在客户 → 商机 → 合同 → 回款流程任意位置都能说出当前对象和上一级对象；
- 返回上一级不会取消已提交操作；
- 关闭整个流程和返回上一级的行为可区分；
- 连续打开关联对象后无无法关闭、遮罩失控或焦点丢失；
- 低高度桌面和移动端主要内容可达，滚动容器数量有明确解释；
- CustomerDetailSheet 的任务划分能通过可用性测试验证。

## 6. 交付物

- 对象上下文栈交互稿；
- CustomerDetailSheet 信息架构方案；
- 详情层级和返回/关闭规则；
- 滚动容器清单；
- 关键对象链路测试记录。

## 7. 后续拆票

建议拆为：客户详情信息架构、对象上下文组件、返回/关闭行为、关联对象切换、焦点恢复、滚动容器治理、商机到回款链路迁移。
