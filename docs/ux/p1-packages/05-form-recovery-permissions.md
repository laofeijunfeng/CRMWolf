# P1-PKG-05 表单错误、权限和未保存恢复 PRD

- **定位**：业务表单可恢复性改造包
- **优先级**：P1
- **适用模块**：CustomerEdit、客户信息、联系人、成员、部署、发票抬头、商机、合同、回款表单
- **不含范围**：Agent / AI 自动化

## 1. 目标

在详情加载失败、选项加载失败、字段校验失败、权限不足、网络失败和并发修改时，保留用户上下文和输入，并提供明确的恢复路径。

## 2. 当前问题

`CustomerEdit` 的详情加载失败存在返回上一页的路径，选项加载失败可能只记录日志。客户信息本身包含多类维护任务，多个 Dialog 叠加时错误和未保存状态容易被遮蔽。

## 3. 本期需求

### 错误分类

- **字段校验**：说明字段和格式，聚焦字段修复；
- **权限不足**：说明受限动作和所需权限，提供联系或申请入口；
- **网络/超时**：说明请求未完成，必要时查询最终状态；
- **服务错误**：保留输入，提供重试或稍后处理；
- **并发修改**：提示数据已变化，提供刷新、查看差异或重新编辑；
- **部分成功**：列出已完成和未完成部分。

### 交互要求

1. 详情加载失败不得默认自动返回；
2. 选项加载失败指出受影响字段并提供重试；
3. 提交后聚焦首个错误，并提供可被读屏发现的错误摘要；
4. 保存失败保留客户、联系人、金额、日期和理由等输入；
5. 未保存退出时提供保存、继续编辑和放弃；
6. 空状态区分无数据、筛选无结果、尚未创建和无权查看；
7. 并发修改不得诱导用户重复创建或覆盖他人数据。

## 4. 独立验收标准

- 断网、超时、权限不足、选项加载失败和校验失败时无需重新填写全部内容；
- 错误与控件关联，键盘和读屏可找到首个错误；
- 详情加载失败不丢失原页面上下文；
- 权限问题不会被误呈现为普通系统故障；
- 未保存退出行为可预测；
- 并发修改有明确且可执行的恢复路径。

## 5. 交付物

- 表单错误分类和文案规范；
- 表单状态处理模板；
- CustomerEdit 及客户信息表单迁移；
- 未保存退出和并发修改交互稿；
- 错误恢复回归测试。
