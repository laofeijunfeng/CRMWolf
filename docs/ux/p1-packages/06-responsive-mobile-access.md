# P1-PKG-06 响应式、滚动和移动端可达性 PRD

- **定位**：小屏和移动端关键任务改造包
- **优先级**：P1
- **适用模块**：Customers、CustomerTracking、Contracts、DataTable、CustomerDetailSheet 及关键表单
- **不含范围**：Agent / AI 自动化

## 1. 目标

确保客户跟进、客户维护、商机审批和回款登记在小屏、低高度、横屏和软键盘环境下仍可完成，避免固定高度和嵌套滚动造成内容不可达。

## 2. 当前问题

多个列表使用 `calc(100vh - ...)` 等固定高度，DataTable 内部还有固定表格区和内部滚动；详情 Sheet、Dialog 和表单可能形成多重滚动。静态代码无法证明 320px、横屏和软键盘场景中的核心内容可达。

## 3. 本期需求

- 桌面大屏可保留高密度固定表格区，低高度场景必须可自适应；
- 移动端优先自然页面滚动，避免多个滚动容器互相遮挡；
- 使用动态 viewport 和 safe area 时验证软键盘打开后的实际行为；
- 主要字段、错误、提交按钮和返回入口在窄屏和放大字体下可达；
- Card、Sheet 和表单操作入口不被固定高度裁切；
- 识别并消除横向溢出、粘性区域冲突和无法滚动到的内容；
- reduced motion 不得影响状态反馈和导航理解。

## 4. 验收环境

320px 宽度、手机横屏、软键盘打开、低高度桌面、safe area、200% 字体、低带宽和断网。

## 5. 独立验收标准

- 四条关键任务在 320px、横屏和软键盘场景下可完成核心操作；
- 低高度桌面不会把工具栏、主要内容和分页同时挤出可视区域；
- 不出现被软键盘遮挡的字段、不可点击的提交按钮或无法关闭的 Sheet；
- 用户能够理解当前需要滚动的区域；
- Card、详情和表单在移动端不出现横向溢出；
- reduced motion 下功能和状态反馈保持完整。

## 6. 交付物

- 响应式场景矩阵；
- 列表、详情和表单滚动容器调整方案；
- 移动端关键任务交互稿；
- 真机和不同 viewport 验收记录；
- 小屏回归用例。
