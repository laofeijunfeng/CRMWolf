# P1-PKG-07 键盘、读屏和无障碍关键任务验收 PRD

- **定位**：横向无障碍验收与回归改造包
- **优先级**：P1，作为所有关键任务的发布门禁
- **适用模块**：DataTable、Dialog、AlertDialog、Sheet、表单和状态反馈
- **不含范围**：Agent / AI 自动化

## 1. 目标

将无障碍从“检查 aria 属性”提升为真实业务任务验收，确保键盘和读屏用户能够理解对象、状态、错误和操作结果。

## 2. 当前问题

DataTable 使用整行交互、tabindex 和上下文菜单键盘支持，需要实测原生表格语义与按钮语义是否冲突。Dialog、Sheet、行内按钮和错误状态的焦点行为也需要全链路验证，不能只依据代码属性数量判断可用性。

## 3. 本期需求

### 键盘

- 明确 Tab 顺序；
- Enter / Space 行操作行为一致；
- ContextMenu 键和 `Shift + F10` 可发现且行为可预测；
- Dialog / Sheet 支持合理的焦点进入、焦点恢复和 Escape；
- 行内按钮不会重复触发行点击。

### 读屏

- 读出对象名称、对象类型、关键状态和操作结果；
- Dialog 有正确标题和描述；
- 字段错误与控件关联，错误摘要可被发现；
- 加载、保存中、成功、失败和权限不足可被辅助技术感知；
- 成功、失败、风险和权限状态不依赖颜色单独表达。

### 任务范围

客户跟进、客户维护、商机审批和回款登记四条关键路径，均覆盖 happy path 和至少一条异常恢复路径。

## 4. 独立验收标准

- 使用键盘完成四条关键任务及异常恢复；
- 使用至少一种主流桌面读屏完成列表、详情、表单和弹窗操作；
- 表格行、行内按钮和菜单不会产生冲突或重复语义；
- 首个错误、保存中、成功、失败和权限不足状态均可理解；
- 发现阻断核心任务的无障碍问题时，相关改造包不得发布完成；
- 输出问题分级、复现路径和修复回归记录。

## 5. 交付物

- 无障碍关键任务测试脚本；
- 键盘验收记录；
- 读屏验收记录；
- 问题分级与修复清单；
- 发布前无障碍回归门禁。
