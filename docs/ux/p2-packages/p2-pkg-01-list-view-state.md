# P2-PKG-01 列表视图状态透明化与渐进披露 PRD

- **文档状态**：PRD 初稿，待产品、设计、研发评审
- **版本**：v0.1
- **日期**：2026-09-04
- **上级文档**：CRMWolf 非 Agent P2 UX 优化 PRD
- **改造包**：P2-01
- **范围**：非 Agent；不重复建设 DataTable 基础能力

## 1. 目标与结论

DataTable 的搜索、筛选、排序、分页、列配置、自定义视图、固定高度和内部滚动已经实现。本改造包不新增这些能力，而是让用户在关闭弹层后仍能理解当前列表为什么呈现这些数据，并降低工具栏的首屏选择成本。

## 2. 用户问题

用户打开筛选、排序或列配置后可以完成设置，但返回列表后不容易持续确认当前生效条件。筛选、排序、隐藏列和自定义视图同时存在时，当前视图定义缺少稳定摘要；高级工具全部平铺时，也增加了认知负担。

## 3. 覆盖范围

首批覆盖 Customers、CustomerTracking、Leads、Opportunities、Contracts、PaymentPlans、PaymentRecords、Invoices、ApprovalCenter。

## 4. 产品需求

**工具分层。** 搜索、刷新和页面最常用筛选入口默认可见；排序、列配置、保存/管理视图等低频工具归入“更多设置”或等价的高级工具入口。入口仍需可发现，不得变成隐藏功能。

**当前状态摘要。** 在表格顶部稳定展示当前视图名称/范围、已生效筛选数量、排序状态和隐藏列数量。无条件时显示“全部数据”或页面默认语义。

**条件移除。** 已生效筛选支持单项移除；提供清除筛选入口，并明确清除筛选不会影响排序、列显示和已保存视图，除非页面已有明确不同规则。

**视图切换反馈。** 切换内置 Tab 或自定义视图时显示轻量的“正在应用视图”状态。应用失败时保留原数据和上下文，提供局部重试，不要求刷新整页。

**请求状态一致。** 筛选、排序和视图切换后分页回到第一页；摘要必须与实际请求参数一致；列表固定高度、内部滚动和分页位置保持不变。

## 5. 不在范围内

- 不新增筛选、排序、列配置或自定义视图后端能力；
- 不改变 DataTable 固定高度、表头固定、内部滚动和移动端 Card 行为；
- 不改变已有视图的权限、数据范围和持久化业务规则；
- 不将本改造包扩展为列表视觉重做。

## 6. 验收标准

- 关闭筛选、排序、列配置弹层后，用户仍能看到当前视图主要状态；
- 无筛选、单条件、多条件、无结果和清除筛选均有明确表现；
- 视图应用中不会出现整页空白或错误的旧视图名称；
- 视图应用失败时原数据和上下文保留，局部重试可恢复；
- 条件改变后分页回到第一页，表格仍保持固定高度和内部滚动；
- 桌面窄屏和移动端下摘要不遮挡主要操作；
- 主要列表的工具命名和摘要结构一致。
