# P2-PKG-02 行操作语义与跨页面一致性治理 PRD

- **文档状态**：PRD 初稿，待产品、设计、研发和业务负责人评审
- **版本**：v0.1
- **日期**：2026-09-04
- **上级文档**：CRMWolf 非 Agent P2 UX 优化 PRD
- **改造包**：P2-02
- **范围**：非 Agent；不重复建设行操作入口

## 1. 目标与结论

系统已经具备桌面主操作、更多菜单、右键菜单、键盘菜单和移动端操作区。本改造包不再增加入口，而是治理同类操作在不同页面和不同承载形式下的命名、主次层级、禁用原因和结果反馈。

## 2. 用户问题

用户在客户、商机、合同、回款和审批列表中会反复遇到“查看/详情、完成/关闭、提交、撤回、下载、删除”等动作。同一动作如果命名或位置不同，用户需要重新学习；按钮仅置灰而不说明原因时，用户也无法判断下一步。

## 3. 产品需求

**动作词典。** 建立跨页面动作词典，明确查看/详情、编辑、完成/关闭、提交、撤回、驳回、删除、下载、复制和更多等词的使用边界。名称表达业务结果，避免无理由的同义混用。

**主次规则。** 高频且低风险的当前任务动作作为主操作；低频、危险或需要确认的动作进入更多菜单；行点击打开详情与显式查看动作的关系保持一致。

**多入口一致。** 同一动作在桌面按钮、更多菜单、右键菜单和移动端 Card 中保持相同名称、可用性、禁用原因和结果语义。设备差异只改变承载形式，不改变动作含义。

**禁用原因。** 对权限不足、状态不允许或缺少前置数据导致的不可用动作，提供简短且可理解的原因。

**反馈一致。** 反馈明确指向操作对象和最终结果；失败沿用 P1 的错误分类、保留上下文和恢复规则，不另建页面私有反馈体系。

## 4. 不在范围内

- 不撤回现有可见主操作、更多菜单、右键、键盘和移动端入口；
- 不把所有操作强制平铺；
- 不改变后端权限判断、业务状态机和高风险确认规则；
- 不以调整操作列对齐或单纯增大列宽作为本改造包目标，除非审计发现具体页面回归。

## 5. 覆盖范围

首批覆盖 Customers、CustomerTracking、Leads、Opportunities、Contracts、PaymentPlans、PaymentRecords、Invoices、ApprovalCenter，以及包含行操作的详情内列表。

## 6. 验收标准

- 主要列表均有动作词典映射；
- 同一动作不存在无理由的多种叫法；
- 同一动作在至少两种入口下名称、禁用原因和结果反馈一致；
- 主操作数量和选择规则可解释；
- 危险操作不会因可见性而被提升为默认主操作；
- 不可用动作能够说明原因或前置条件；
- 操作列不出现按钮裁切、遮挡或因动作变化产生明显跳动。
