# P2-PKG-03 页面动作收尾与下一步导航一致性 PRD

- **文档状态**：PRD 初稿，待产品、设计、研发和业务负责人评审
- **版本**：v0.1
- **日期**：2026-09-04
- **上级文档**：CRMWolf 非 Agent P2 UX 优化 PRD
- **改造包**：P2-03
- **范围**：非 Agent；依赖 P1 状态反馈和错误恢复规范

## 1. 目标与结论

系统已经具备操作级 Toast、列表刷新、部分下一步 Dialog 和 P1 的结果反馈基础。本改造包不重做提交、确认和错误处理，而是统一低风险保存、状态推进、审批和财务常规操作完成后的收尾方式，让用户知道结果、对象状态和合理下一步。

## 2. 用户问题

不同页面的操作完成后，有时只刷新列表，有时只显示短时 Toast，有时打开下一步 Dialog。用户可能知道请求结束，却不知道对象最终状态、下一步可做什么，以及是否应继续留在当前上下文。

## 3. 覆盖任务

- 客户信息保存；
- 客户跟进完成；
- 商机状态推进；
- 合同/审批提交；
- 回款登记和回款计划常规更新；
- 发票相关常规保存。

## 4. 产品需求

**低风险保存。** 保存成功后保留当前页面或详情上下文，明确提示哪个对象已保存。存在明显下一步时，提供非阻塞的查看详情、继续创建或返回列表入口，不强制追加弹窗。

**状态推进。** 完成、关闭、提交、审批等操作成功后显示对象最终状态和当前可执行的后续动作；列表、详情和操作按钮同步更新，避免继续显示旧状态。

**财务常规操作。** 回款登记、计划更新和发票保存完成后明确显示结果对象，以及是否需要后续审批。结果未知时继续使用 P1 的查询、重试或人工确认语义，不直接提示成功。

**返回与焦点。** 从 Sheet 或 Dialog 完成操作后，返回到可预测的列表行、详情分区或触发按钮；收尾反馈不打断用户原本的浏览上下文。

**反馈强度分级。** Toast 只承担短反馈；影响后续业务的结果使用页面内状态、对象状态或可进入详情的持久反馈；不为每次成功都增加第二个弹窗。

## 5. 不在范围内

- 不改变业务动作、审批链、状态机和接口契约；
- 不强制跳转详情页或统一跳转到某个页面；
- 不取消已有的必要下一步 Dialog；
- 不把 P1 高风险操作降级为普通 Toast；
- 不新增业务对象或后续操作能力。

## 6. 验收标准

- 覆盖上述至少 5 类代表性任务；
- 每个任务均有明确的成功结果、对象最终状态和下一步表达；
- 成功后列表、详情和按钮状态不长期停留在旧数据；
- 用户无需刷新即可判断常规操作是否生效；
- 低风险操作不会被无必要的二次弹窗打断；
- 从 Sheet/Dialog 返回后仍能回到原列表上下文或原触发位置；
- 失败、超时和结果未知场景继续符合 P1 恢复规范。
