# P2-PKG-04 设计系统迁移治理与共享状态组件收敛 PRD

- **文档状态**：PRD 初稿，待产品、设计、研发评审
- **版本**：v0.1
- **日期**：2026-09-04
- **上级文档**：CRMWolf 非 Agent P2 UX 优化 PRD
- **改造包**：P2-04
- **范围**：非 Agent；不进行全量视觉换肤

## 1. 目标与结论

设计系统已经存在 V2 语义 Token、焦点、禁用、主题、动效和组件规范，但源码中仍有旧 Token、raw color、页面级重复样式和状态组合分叉。本改造包的目标是建立迁移清单和新增代码门禁，优先收敛共享组件和高频页面，不做一次性全站视觉重做。

## 2. 用户与系统问题

颜色、状态、间距和空/加载/错误反馈如果在多个页面重复实现，后续很容易再次出现视觉和行为差异。用户感知到的是页面不一致，研发承担的是修改成本和回归风险。

## 3. 首批范围

优先审计和迁移：

- `AppLayout.vue`；
- `SalesDashboard.vue`；
- `MetricCard.vue`；
- `TopBarTabs.vue`；
- `PaymentPlanDetailContent.vue`；
- 高频 Empty、Loading、Error、Feedback 组合；
- 设计系统检查脚本和迁移文档。

## 4. 产品需求

**迁移清单。** 以具体代码位置记录旧 Token/raw color、目标 Token、负责人、状态和回归风险，按共享组件、高频页面、低频页面排序。

**新增代码门禁。** 新增或修改的业务样式不得继续引入可由语义 Token 替代的 raw hex、rgba 或历史 Token。必要例外必须有明确说明并登记。

**共享组件优先。** 先处理被多个页面复用的颜色、状态、卡片、Tab、空状态、加载态、错误态和反馈组合，再处理单页遗留点。

**状态组合收敛。** 为空、加载、错误、无结果和操作反馈提供推荐组合和使用边界；保留页面所需的业务文案，不要求所有页面视觉完全相同。

**迁移回归。** 重点验证亮色/暗色主题、状态色对比度、焦点环、禁用态、移动端布局和 reduced motion，不得破坏 P1 可达性。

## 5. 不在范围内

- 不进行品牌色、圆角、阴影和全量视觉重构；
- 不强制一次性删除兼容层；
- 不为清理样式修改业务组件行为、页面高度或 DataTable 滚动模型；
- 不把设计系统治理扩大为与本期 UX 问题无关的架构重构。

## 6. 验收标准

- 有可追踪迁移清单，覆盖已确认共享组件和高频页面遗留点；
- 检查规则能够识别主要旧 Token/raw color，并支持合理例外；
- 共享组件状态色、焦点、禁用态和主题表现通过回归；
- 空/加载/错误/无结果组合不再因页面复制造成明显语义分叉；
- 迁移不导致 DataTable 固定高度、内部滚动、操作列和移动端布局回归；
- 设计系统实现状态文档与源码审计结果保持同步。

## 7. 交付物

交付迁移清单、Token 使用检查规则、共享状态组件推荐用法、组件回归记录和设计系统实现状态更新。
