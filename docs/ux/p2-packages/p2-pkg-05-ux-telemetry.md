# P2-PKG-05 关键任务性能与反馈度量 PRD

- **文档状态**：PRD 初稿，待产品、研发、UX 和安全/合规负责人评审
- **版本**：v0.1
- **日期**：2026-09-04
- **上级文档**：CRMWolf 非 Agent P2 UX 优化 PRD
- **改造包**：P2-05
- **范围**：仅普通业务；Agent / AI 自动化及相关指标排除

## 1. 目标与结论

当前系统有 Axios 请求和超时处理，也有部分页面的局部请求状态，但没有统一的前端 UX telemetry。系统无法稳定判断用户点击后多久获得首个反馈、多久完成、是否重复点击、失败后是否重试，以及等待主要来自接口还是界面更新。

本改造包先建立事件模型和基线，不在没有数据的情况下直接规定所有接口必须达到同一个绝对耗时。

## 2. 首批任务范围

- 客户保存；
- 客户跟进完成；
- 商机状态推进；
- 合同/审批提交；
- 回款登记；
- 列表首次加载和刷新；
- 筛选、排序和视图应用。

## 3. 产品需求

**事件模型。** 普通业务事件至少包括任务开始、首个可见反馈、请求完成、成功、失败、重试、取消和结果未知。每次关键任务生成不可识别用户和业务内容的 interaction id。

**时间指标。** 记录点击到首个反馈、点击到请求结束、请求结束到界面完成更新；列表补充首屏可交互时间和刷新完成时间。

**结果模型。** 成功、失败、重试、取消和结果未知必须可区分；能够识别短时间内的重复点击，不依赖业务文本猜测结果。

**数据最小化。** 仅记录页面、动作类型、结果类型、HTTP 状态类别、耗时区间、重试次数和是否重复点击等必要维度。不得记录客户名称、合同金额、回款金额、自由文本和完整请求参数。

**异常分析。** 支持按页面、动作类型和结果类别查看长尾耗时、失败率、结果未知率、重试率和重复点击率；与 P1 错误分类和恢复路径关联。

**非阻塞接入。** telemetry 采集失败、网络不可用或采集服务异常不能影响主流程，也不能增加额外确认或表单。

## 4. 不在范围内

- 不改变接口超时策略、业务请求顺序和用户可见流程；
- 不因埋点增加阻塞式交互；
- 不采集 Agent / AI 任务指标；
- 不采集业务敏感信息；
- 不在首期直接承诺未经基线验证的绝对性能指标。

## 5. 验收标准

- 首批关键任务均能产生可关联的开始、首反馈和最终结果事件；
- 成功、失败、重试、取消、结果未知和重复点击能够区分；
- 事件不包含客户、合同、金额和自由文本等敏感内容；
- 埋点异常不影响主流程；
- 能生成页面/动作维度的基础耗时和结果报表；
- 产品、研发和 UX 能据此确定下一轮性能优化对象。
